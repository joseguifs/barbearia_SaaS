## Sprint 3: Criação das APIs para consumo interno e refatoração no código

**Valor da Sprint:**  
Integração de APIs para melhor design arquitetural, separação de responsabilidades, consumo interno e refatoração do código.

---

## Funcionalidades

### 1. API de agendamento, autenticação e refatoração (APIs)

**Descrição:**  
Essa funcionalidade visa permitir a integração de APIs de autenticação e agendamento ao nosso sistema utilizando o `fetch` do JavaScript, separando as responsabilidades entre front-controller e backend.

**Desenvolvida por:** José Guilherme Ferreira Sobrinho

---

### 2. API de serviço

**Descrição:**  
Essa funcionalidade visa permitir o desenvolvimento e a disponibilização da API de serviço no nosso sistema, uma vez que antes só podíamos realizar a inserção de novos serviços via SQL. Dessa forma, utilizando o Postman, podemos consumi-la dentro do nosso sistema usando `fetch`.

**Desenvolvida por:** Matheus Felipe Lopes Valadares

---

### 3. API de barbeiro e testes unitários

**Descrição:**  
Essa funcionalidade visa permitir o desenvolvimento e a disponibilização da integração da API de barbeiro, de forma que possamos realizar operações básicas de CRUD sobre essa entidade, além do desenvolvimento de testes unitários, visando testar o comportamento e a execução das funcionalidades do sistema.

**Desenvolvida por:** Matheus Felipe

---

### 4. API de clientes

**Descrição:**  
Essa funcionalidade visa permitir o desenvolvimento e a disponibilização da integração da API de clientes. Dessa forma, o sistema passa a executar operações básicas sobre a entidade cliente, as quais antes só podiam ser executadas por meio de SQL, além de podermos integrá-la às responsabilidades relacionadas à entidade cliente.

**Desenvolvida por:** José Carlos
